# PrepStack

אתר הכנה לראיונות עבודה בהייטק ולמידת טכנולוגיות: תוכנית לימודים אישית שנבנית ממחקר עדכני ברשת, שיעורים בשישה פורמטים שמותאמים ללומד לפי הציונים והמשוב שלו, מבחן בסוף כל שיעור (קוד שרץ מול בדיקות, לוח ארכיטקטורה עם ציון וביקורת, משימה מעשית או מבחן ידע), סימולציות ראיון עם מראיין AI, מסלול AI ואייג'נטים ולוח התקדמות.

## איך זה בנוי

| חלק | איפה | מה עושה |
|---|---|---|
| האתר | `src/` | React + Vite + TypeScript, ממשק בעברית (RTL) |
| מנוע ה-AI | `netlify/functions/` | Netlify Functions שקוראות ל-Claude API. מפתח ה-API נמצא רק בשרת |
| דאטהבייס והזדהות | Supabase | פרויקט ייעודי. כתובת ומפתח ציבורי ב-`shared/config.ts` |
| קוד משותף | `shared/` | קטלוג תפקידים, פורמטים וסוגי ראיונות; כתובת Supabase |

- `ai-job-background` : עבודות ארוכות (מבחן מיקום, תוכנית, שיעור, בדיקת מבחן, משוב על ראיון, ניתוח משרה). האתר מכניס שורה ל-`prep_jobs`, הפונקציה כותבת לתוכה את התוצאה.
- `chat` : תור שיחה בסטרימינג (מראיין, עוזר AI בתוך ראיון, מורה בשיעור).
- `refresh-maps` : רץ כל יום שני ומרענן מהרשת את "מפות התפקיד" שהתיישנו, כדי שהתוכניות יתעדכנו בטכנולוגיות חדשות.

אלגוריתם התאמת הפורמט נמצא ב-`src/domain/FormatSelector.ts` (Thompson sampling: התגמול הוא 75% ציון המבחן ו-25% דירוג הלומד, בהקשר של סוג הנושא). חזרה במרווחים ב-`src/domain/SpacedRepetitionScheduler.ts`.

## מבנה התיקיות

האתר בנוי בשכבות, וכל שכבה תלויה רק בשכבות שמתחתיה:

```
src/
  domain/       מודלים: מחלקות בלי גישה לרשת או לדאטהבייס (Topic, Lesson, StudyPlan, LearnerProfile, MockInterview,
                TopicList, ProgressReport, FormatSelector, SpacedRepetitionScheduler, PlacementTest...). records.ts = צורת השורות בדאטהבייס.
  data/         גישה לנתונים: הממשק Database (Supabase או הדגמה בדפדפן), AuthService, ו-repositories שהופכים שורות למודלים
  ai/           הממשק AiEngine עם חוזה טיפוסי לכל סוג עבודה; מימוש לשרת ומימוש להדגמה
  services/     שירותי האפליקציה: PlanService, StudyService, InterviewService, ProgressService, OnboardingService...
  app/          נקודת הכניסה, ניתוב, AppServices (המקום היחיד שמחליט על המימושים), AppContext (useServices, useLearner)
  features/     מסך לכל יכולת. מסכים מדברים רק עם services ומודלים, לא עם הדאטהבייס
  components/   רכיבים משותפים: עורך קוד, לוח ארכיטקטורה, צ'אט, תצוגת ביקורת
  styles/       עיצוב
shared/         קוד שמשותף לאתר ולשרת (כולל החוזה של לוח התחזוקה)
netlify/functions/  פונקציות השרת: _core (בקשה, שגיאות, ולידציה, handlers לעבודות), _services, _adapters, _lib (Claude)
supabase/       סכמת הדאטהבייס
```

כללים: מודלים הם immutable (מתודה שמשנה מחזירה מופע חדש); שמות משתנים מלאים (`topic`, לא `t`); מספרי קסם הופכים לקבועים עם שם; מצב הדגמה הוא מימוש נוסף של אותם ממשקים, לא `if (DEMO)` בתוך הקוד.

ייבוא בתוך האתר נעשה עם `@/...` (לתוך `src`) ו-`@shared/...`.

## הרצה מקומית במצב הדגמה

```bash
npm install
```

```bash
npm run demo
```

מצב הדגמה לא צריך שרת: הנתונים נשמרים בדפדפן ותשובות ה-AI הן תוכן לדוגמה (`src/ai/demo/`). מתאים לבדיקת הממשק בלבד.

## העלאה לאוויר

1. **דאטהבייס**: ב-Supabase, SQL Editor, להדביק ולהריץ את `supabase/schema.sql` (פעם אחת; בטוח להריץ שוב).
2. **GitHub**: ליצור ריפו ולדחוף אליו את התיקייה הזו.
3. **Netlify**: Add new site, Import from Git, לבחור את הריפו. הגדרות הבנייה נקראות מ-`netlify.toml`.
4. **משתני סביבה ב-Netlify** (Site configuration, Environment variables):
   - `ANTHROPIC_API_KEY` : מפתח מ-console.anthropic.com
   - `SUPABASE_SERVICE_ROLE_KEY` : מ-Supabase, Project Settings, API (המפתח הסודי, לא ה-anon)
   - לא חובה: `CLAUDE_MODEL` לשיעורים, תוכניות ובדיקות (ברירת מחדל `claude-sonnet-5-5`), `CLAUDE_CHAT_MODEL` למראיין ולמורה (ברירת מחדל `claude-haiku-5-5`), `AI_DAILY_LIMIT` (ברירת מחדל 60 בקשות AI למשתמש ביום)
5. לפרוס מחדש אחרי הוספת המשתנים.

### לדעת מראש

- **עלות**: כל תוכנית, שיעור, בדיקה ותור בראיון הם קריאה ל-Claude. המכסה היומית למשתמש מגבילה את זה. למשתמש אחד פעיל זה בערך 2-5$ בחודש. מומלץ לקבוע תקרת הוצאה ב-Anthropic Console.
- **הרשמה באימייל**: אם "Confirm email" מופעל ב-Supabase, נרשמים מקבלים מייל אימות. השירות המובנה של Supabase שולח רק כמה מיילים בשעה; לקהל גדול צריך SMTP משלכם.
- **מגבלת זמן**: תור שיחה רץ בפונקציה רגילה (עד כדקה ב-Netlify); כל השאר ברקע (עד 15 דקות).

## צד השרת (גרסה 2, נובמבר 2026)

- **הדפדפן שולח רק מזהים ובחירות.** כל עבודת AI עוברת דרך `ai-job-background`: השרת בודק את הבקשה עם zod, יוצר בעצמו את שורת העבודה, טוען את הנושא והפרופיל מהדאטהבייס ובונה את הקלט למודל. ציוני מבחנים מחושבים ונשמרים בשרת בלבד (עבודת `complete`).
- **מטמון שיעורים משותף.** שיעור נוצר פעם אחת לכל נושא × פורמט × רמה (junior/mid/senior) × חזרה או שיעור מלא, ומוגש לכל מי שמתאים. לכל שיעור 4 מבחנים בהתחלה ועד 6, כדי שבחזרה לא יופיע מבחן שכבר נראה. ההערה על נקודות החולשה נשארת אישית ונכתבת ב-AI. השיעור מתעדכן רק כשמישהו פותח אותו אחרי שסומן לעדכון (דירוג נמוך, דיווחי טעות, שינוי בשוק), ולכל היותר פעם בשבוע.
- **הפעלה הדרגתית.** חלק הלומדים שמקבלים שיעורים מהמטמון נקבע בלוח התחזוקה (ברירת מחדל 10%).
- **בקשות נושא של לומדים** מסווגות: פרטיות נשארות פרטיות, כלליות מחכות לאישור מתחזק לפני שהן נכנסות לרשימה המשותפת.
- **מחברת טעויות ותרגול יומי** (`/practice`): תשובות שגויות במבחנים, בעיות חמורות מהביקורת ורגעים מרכזיים מראיונות נשמרים במחברת (`prep_mistakes`) וחוזרים בשיטת Leitner (5 תאים: 1, 3, 7, 14 ו-30 יום). התרגול היומי: עד 8 פריטים, קודם טעויות שהגיע זמנן ואז שאלות וכרטיסים משיעורים שהושלמו, מעורבבים בין נושאים. הלוגיקה ב-`src/domain/Mistake.ts` וב-`src/domain/DailyPractice.ts`.
- **לוח תחזוקה** בכתובת `/admin`: משתמשים, עלויות AI לפי יום, שימוש ומודל, שיעורים ומטמון, עבודות שנכשלו, שגיאות, ובקשות נושא לאישור. רק מי שרשום ב-`prep_maintainers` רואה אותו.
- **ניטור:** כל שגיאה בדפדפן ובשרת נשמרת ב-`ops_events`; כל קריאה ל-Claude נרשמת עם טוקנים ועלות ב-`ops_ai_usage`; כל בקשה מקבלת מזהה (`x-request-id`) שמופיע בלוגים, בעבודות ובשגיאות.

### בדיקות

```bash
npm run check          # טיפוסים, lint, בדיקות יחידה ובנייה (כמו ב-CI)
npm run eval:lessons -- --dry-run   # מה תריץ בדיקת איכות השיעורים
npm run eval:lessons   # יוצר 4 שיעורים לדוגמה ובודק אותם (צריך ANTHROPIC_API_KEY, עולה כסף)
```

להריץ את `eval:lessons` לפני כל שינוי בפרומפטים של השיעורים, ולהעלות את `PROMPT_VERSION` ב-`shared/lessonKeys.ts` כשהשינוי צריך לייצר שיעורים חדשים במטמון.
